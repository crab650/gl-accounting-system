# 程式碼知識庫的類型欄位

知識庫的 `symbol_type` 用來標示「這篇分析解釋的是哪一種程式元素」，與會計科目的 `type`（資產、負債等）不同。本專案已保存的七篇分析都對應 `app/services.py` 中的獨立 Python 函式，因此使用 `function`。

| `symbol_type` | 中文意思 | 適用情況 |
|---|---|
| `class` | 類別 | 一整個類別及其職責 |
| `method` | 方法 | 定義在類別內的函式 |
| `function` | 函式 | 不屬於類別的函式；本專案七篇分析使用此值 |
| `controller` | 控制器 | 接收請求、協調處理並回應的程式元素 |
| `service` | 服務 | 集中實作業務規則的程式元素 |
| `mapper` | 映射器 | 在程式資料與資料庫操作之間做對應的程式元素 |
| `repository` | 資料存取層 | 封裝資料讀寫的程式元素 |
| `component` | 元件 | 可重用的功能單元，例如前端元件 |
| `sql` | SQL | 要解釋的查詢或資料庫指令 |
| `other` | 其他 | 前面類型都不適合的程式元素 |

以上是分類標籤，不表示程式的執行權限或資料型態。例如 `app/services.py` 雖然是服務層檔案，其中的 `post_voucher()` 仍是 Python 獨立函式，因此本次標為 `function`；若分析對象是一整個服務物件，才可視目的使用 `service` 或 `class`。

若知識庫頁面出現 `sql_type`，那是另一個欄位：`SELECT` 查詢、`INSERT` 新增、`UPDATE` 更新、`DELETE` 刪除、`MERGE` 合併、`PROCEDURE` 預存程序、`FUNCTION` 資料庫函式、`OTHER` 其他。本次七篇分析的原始碼沒有手寫 SQL，因此沒有建立 SQL 片段。

可用代碼依本專案的 [Agent 使用指南](../AGENT_CODE_EXPLANATION_GUIDE.md) 整理。
